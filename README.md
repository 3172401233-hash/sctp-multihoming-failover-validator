# sctp-multihoming-failover-validator

验证 SCTP 多宿主路径切换、心跳和重传状态。

## 范围说明

**这是一个关联状态模拟器，不构造、解析或收发任何真实 SCTP 报文。**
没有 IP  socket、没有 SCTP 公共头/块格式、没有校验和与验证标签；
它只在离散时间片上模拟 RFC 4960 风格的关联/路径状态机、定时器与
错误计数器语义，用于验证故障切换与重传逻辑是否正确。

## 模拟的语义

- 每个关联持有多条路径（主/备），每条路径有独立的 HEARTBEAT 定时器
  和错误计数；数据重传使用独立的 RTO 定时器（指数退避、封顶）。
- 路径错误计数（心跳超时或 RTO 超时）超过 `path_max_retrans` 时，
  路径变为 `INACTIVE` 并触发故障切换；关联错误计数超过
  `assoc_max_retrans` 时关联进入 `CLOSED`。
- 心跳成功只清零错误计数：**不代表数据路径可用**，不确认任何数据。
- 恢复的路径变为 `ACTIVE`，但**不会立刻替代仍有效的当前数据路径**；
  仅当当前没有可用路径时才会被选为数据路径。
- 数据只发送到 `ACTIVE` 路径；没有可用路径时重传被推迟。
- SACK 累积点只前进不后退（容忍乱序/过期 SACK）；支持间隙块、
  重复 TSN 报告与快速重传；部分消息只重传未确认的分片。

## 输入与输出

输入（`sctp_sim.Association`）：端点地址（`add_path`）、主备路径、
`hb_interval`、`rto_initial`/`rto_max`、`path_max_retrans`、
`assoc_max_retrans`、发送队列（`send_message`，可分片）、
链路通断（`set_link`）、SACK 丢失开关（`drop_sacks`）、
直接注入 SACK（`inject_sack`，用于乱序/重复/部分确认场景）。

输出（`assoc.report()`）：每条路径状态与错误计数、当前数据路径、
每次发送实际经过的路径（`transmissions`）、未确认块
（`unacked_tsns`）、重复 TSN、关联最终状态与完整事件日志。

## 运行

需要 Python 3.8.2+（仅标准库）。

```sh
python -m unittest        # 运行全部测试
python -m sctp_sim        # 运行主路径断开 -> 切换 -> 恢复的演示
```

## 测试覆盖

- 主路径断开：RTO 超时累积错误，切换备用路径并完成重传
- 双路径同时故障：全部 INACTIVE，关联错误计数超限后 CLOSED
- 同时故障后单路径恢复：恢复路径在没有可用路径时接管数据
- 路径恢复与主路径抖动：恢复/抖动不立刻替代仍有效的当前路径
- 心跳超时：无数据时仅靠心跳错误计数判定路径失效
- 心跳成功不确认数据：HB-ACK 清零错误计数但未确认块保持不变
- SACK 丢失：RTO 重传，对端报告重复 TSN
- 长时间重传：连续 RTO 指数退避并封顶，最终关联关闭
- 乱序 SACK：累积点不后退；重复 TSN 报告；部分消息重传
